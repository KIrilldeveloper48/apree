# Apree

Локально запускаемый задачник с Kanban-доской. Задачи хранятся в PostgreSQL и доступны через NestJS REST API, поэтому состояние доски сохраняется после обновления страницы.

## Возможности

Базовый функционал:

- три колонки: «Новая», «В работе», «Готово»;
- создание задачи с названием, описанием, приоритетом и целевой колонкой;
- просмотр задачи кликом по карточке, редактирование и удаление с подтверждением;
- смена статуса в окне задачи;
- данные в PostgreSQL через REST API;
- состояния загрузки, ошибки с повторной попыткой и пустой доски;
- адаптивная сетка: три колонки на desktop и одна колонка на узком экране.

Дополнительно к ТЗ реализовано:

- кнопка `+` внизу каждой колонки создаёт задачу сразу с её статусом;
- статус можно выбрать и в общей форме «Новая задача»;
- drag-and-drop карточек между колонками с сохранением статуса в API;
- строка поиска по названию задачи;
- фильтр по приоритету и единая кнопка очистки фильтров;

## Структура проекта

```text
apps/
├── api/                         # NestJS API
│   └── src/tasks/               # DTO, controller, service, helpers и core-тесты задач
└── web/                         # Next.js приложение
    └── src/features/tasks/
        ├── api/                 # Zod-схемы, типы и REST-клиент
        ├── model/               # hook состояния и чистая логика фильтрации/группировки
        ├── components/          # составные компоненты доски и диалогов
        └── ui/                  # небольшие UI-элементы и состояния
prisma/
├── schema.prisma                # модель БД
└── migrations/                  # SQL-миграции
compose.yaml                     # локальный PostgreSQL
```

Каждый собственный type alias или интерфейс находится в отдельном `*.types.ts`; вспомогательные функции — в `*.helpers.ts` рядом с соответствующим модулем.

- Node.js 22+;
- npm 11+;
- Docker Desktop с Docker Compose v2.

Проверка версий:

```powershell
node --version
npm --version

```

## Быстрый запуск

1. Установите зависимости:

   ```powershell
   npm install
   ```

2. Создайте локальный файл окружения:

   ```powershell
   Copy-Item .env.example .env
   ```

3. Запустите PostgreSQL:

   ```powershell
   docker compose up -d db
   ```

4. Примените миграции и сгенерируйте Prisma Client:

   ```powershell
   npm run db:migrate:deploy
   npm run db:generate
   ```

5. В двух отдельных терминалах запустите API и frontend:

   ```powershell
   npm run dev:api
   ```

   ```powershell
   npm run dev:web
   ```

   API запускается через `ts-node` без watch-режима. После изменения backend-кода перезапустите его: остановите процесс `Ctrl+C` и повторно выполните `npm run dev:api`.

Если PowerShell запрещает запуск npm-скриптов, используйте `npm.cmd` вместо `npm`.

Откройте `http://localhost:3000`. API доступен по `http://localhost:3001/api`, Swagger — по `http://localhost:3001/api/docs`.

## API задач

| Метод    | Путь                    | Назначение                                                                                                               |
| -------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `POST`   | `/api/tasks`            | Создать задачу; необязательное поле `status` позволяет сразу выбрать колонку. При отсутствии статуса используется `NEW`. |
| `GET`    | `/api/tasks`            | Получить список задач.                                                                                                   |
| `GET`    | `/api/tasks/:id`        | Получить задачу.                                                                                                         |
| `PATCH`  | `/api/tasks/:id`        | Изменить название, описание или приоритет.                                                                               |
| `PATCH`  | `/api/tasks/:id/status` | Изменить статус задачи.                                                                                                  |
| `DELETE` | `/api/tasks/:id`        | Удалить задачу.                                                                                                          |

Статусы: `NEW`, `IN_PROGRESS`, `DONE`. Приоритеты: `LOW`, `MEDIUM`, `HIGH`.

## Prisma и локальная БД

Схема Prisma находится в `prisma/schema.prisma`, миграции — в `prisma/migrations`. Для новой development-миграции:

```powershell
npm run db:migrate -- --name describe_change
```

Не редактируйте уже применённые миграции. Остановить БД без удаления данных:

```powershell
docker compose down
```

Полное удаление контейнера и локального тома БД — необратимая операция:

```powershell
docker compose down --volumes
```

## Решения и ограничения

- PostgreSQL — единственный источник истины; `localStorage` не хранит задачи.
- Docker Compose ограничен PostgreSQL, потому что NestJS и Next.js удобнее запускать локально с hot reload и средствами отладки.
- Drag-and-drop меняет только колонку задачи; ручная сортировка задач внутри колонки не входит в текущую версию.
- Не реализованы авторизация, вложения и комментарии.

AI помог подготовить структуру проекта, повторяющиеся части frontend/API, документацию и проверки. Каждый результат проверялся ESLint, Prettier, TypeScript, Vitest, production-сборкой и ручными сценариями.

Оценка затраченного времени: около 3 часов на реализацию основного функционала и ещё час-полтора на приведение UI в удобоваримый вид и добавление доп. функционала.
