# Apree

Локальное веб-приложение для управления задачами. Проект состоит из Next.js
клиента, NestJS API и PostgreSQL. Схема задач и начальная миграция уже
подготовлены; API-маршруты и UI доски будут добавляться следующими итерациями.

## Требования

- Node.js 22 или новее;
- npm 11 или новее;
- Docker Desktop с Docker Compose v2 — только для PostgreSQL.

Проверить версии можно командами:

```powershell
node --version
npm --version
docker compose version
```

## Локальный запуск

1. Установите зависимости:

   ```powershell
   npm install
   ```

2. Создайте локальный файл окружения из шаблона:

   ```powershell
   Copy-Item .env.example .env
   ```

   Пароль в шаблоне предназначен только для локальной разработки. Файл `.env`
   исключён из Git.

3. Поднимите PostgreSQL:

   ```powershell
   docker compose up -d db
   ```

4. Примените миграции и сгенерируйте Prisma Client:

   ```powershell
   npm run db:migrate
   npm run db:generate
   ```

5. В двух отдельных терминалах запустите API и web-клиент:

   ```powershell
   npm run dev:api
   ```

   ```powershell
   npm run dev:web
   ```

   В PowerShell с ограниченным выполнением сценариев используйте `npm.cmd`
   вместо `npm`.

## Ручная проверка текущего состояния

1. Выполните шаги локального запуска.
2. Убедитесь, что `docker compose ps` показывает сервис `db` в состоянии
   `healthy`.
3. Выполните `npm exec prisma migrate status`. Вывод должен содержать
   `Database schema is up to date!`.
4. В терминале API дождитесь сообщений об инициализации `PrismaModule` и
   успешном старте NestJS. API слушает `http://localhost:3001`.
5. Откройте `http://localhost:3000` в браузере. Должна отображаться страница с
   текстом «Задачник Apree».

На этой стадии у API ещё нет маршрутов задач: ответ `404` на корневой URL
ожидаем. Пользовательские сценарии появятся в следующих вехах.

## Prisma и миграции

Схема находится в `prisma/schema.prisma`; начальная SQL-миграция — в
`prisma/migrations`. После любого изменения схемы создавайте новую миграцию:

```powershell
npm run db:migrate -- --name describe_change
```

Команда работает только с локальной development-БД. Не редактируйте уже
применённые миграции: добавляйте новые.

## Управление локальной БД

Остановить контейнер без удаления данных:

```powershell
docker compose down
```

Удалить контейнер и локальный том PostgreSQL:

```powershell
docker compose down --volumes
```

Вторая команда необратимо удаляет локальные данные БД.

## Переменные окружения

| Переменная                 | Назначение                                                   |
| -------------------------- | ------------------------------------------------------------ |
| `POSTGRES_DB`              | Имя локальной базы данных.                                   |
| `POSTGRES_USER`            | Пользователь PostgreSQL.                                     |
| `POSTGRES_PASSWORD`        | Пароль локального пользователя PostgreSQL.                   |
| `POSTGRES_PORT`            | Порт PostgreSQL на хосте.                                    |
| `DATABASE_URL`             | Строка подключения Prisma-клиента.                           |
| `API_PORT`                 | Порт API. По умолчанию — `3001`; `PORT` имеет приоритет.     |
| `NEXT_PUBLIC_API_BASE_URL` | Зарезервированный публичный базовый URL API для web-клиента. |

## Текущее состояние и ограничения

- Источником истины для задач станет PostgreSQL; localStorage не будет
  использоваться для постоянного хранения задач.
- Prisma-схема, миграция и подключение API к PostgreSQL добавлены. Маршруты
  задач, Material UI и сама доска пока не реализованы.
- Авторизация, совместное редактирование, вложения и облачное развёртывание не
  входят в объём первой версии.

## Использование AI

времени и принятых решениях.
